## 詳細說明

以下整段貼上（商店欄位為純文字，不支援 Markdown）：

```
YouTube 關閉瀏覽器後還原的是網址，而網址通常不含時間參數，重新打開影片就從 0:00 開始。這支擴充功能把觀看進度存在瀏覽器本機，重新打開同一支影片時接續上次的位置。

功能
・播放時每 2.5 秒記錄一次進度，暫停、換片、切換分頁時補寫
・重新打開影片後自動接續，左下角顯示接續的時間點，可選擇從頭播放
・工具列面板列出最近的觀看記錄，點擊即從該時間點開啟
・廣告播放期間不記錄，避免廣告秒數覆蓋正片進度
・距離片尾 20 秒內視為看完，下次不會被拉回結尾
・網址自帶 t= 時以網址為準
・工具列面板可切換記錄功能的開關

資料存放
記錄存在瀏覽器的本機儲存空間（chrome.storage.local），不會上傳，也沒有分析或追蹤程式碼。

權限
storage：儲存影片 ID 與觀看秒數。內容腳本只在 youtube.com 上執行。

開源
原始碼與問題回報：https://github.com/xygowo/youtube-resume-helper
授權：MIT
```

## 權限理由

### 要求 storage 的理由

```
儲存每支影片的觀看進度：影片 ID、目前秒數、影片長度、標題與更新時間。

用途有兩個：重新開啟同一支影片時接續播放，以及工具列面板的記錄清單。

資料只寫入 chrome.storage.local，不會傳送到任何伺服器，也沒有跨裝置同步或備份。
```

### 要求網站存取權限的理由

manifest 沒有宣告 `host_permissions`，但 `content_scripts.matches` 指定了 YouTube，商店會把這個比對模式視為網站存取權限，所以這個欄位是必填的。

```
內容腳本只在 https://www.youtube.com/* 執行，用途有三個：

1. 讀取播放器的目前時間與影片長度，用來記錄觀看進度。
2. 續播時把播放位置設定回上次的時間點。
3. 監聽 YouTube 的單頁導航事件（yt-navigate-start / yt-navigate-finish），在切換影片前寫入舊影片的進度。

不需要其他網站，也不讀取頁面文字、表單或帳號資料。
```

### 遠端程式碼

選「**不，我沒有使用遠端程式碼**」。所有 JS 都在 zip 內，沒有外部 `<script src>`、沒有 `eval`、沒有動態載入。

選「是」會要求填寫理由並進入額外審查，實際上不需要。

## 資料使用聲明

Chrome 的 [User Data FAQ](https://developer.chrome.com/docs/webstore/program-policies/user-data-faq) 寫得很明確：資料只存在使用者裝置、不傳輸到外部伺服器，**仍然需要揭露**。所以這一頁不能全部不勾。

### 要勾選的資料類型

- [x] **網頁記錄** — 儲存播放過的影片 ID、影片標題與更新時間，等同「造訪過的網頁清單與頁面標題」
- [x] **網站內容** — 同時儲存影片標題與頻道名稱，屬於頁面上的文字

其餘七項（個人識別資訊、健康資訊、財務和付款資訊、驗證資訊、個人通訊資料、位置資訊、使用者活動）都不勾。程式沒有記錄點擊、滑鼠、捲動或按鍵行為。

### 三項認證全部勾選

- 我不會將使用者資料出售或轉移給第三方
- 我不會將使用者資料用於與單一用途無關的目的
- 我不會將使用者資料用於判斷信用或進行放款

### 為什麼不只勾一項

影片 ID 加上更新時間，構成一份存在本機的觀看清單，屬於「網頁記錄」；標題與頻道名稱是頁面上的文字，屬於「網站內容」。少勾會被認定揭露不實，多勾不會被退件。

若只想揭露「網頁記錄」，必須停止儲存標題與頻道名稱（`content/content.js` 的 `saveNow`），工具列面板就只剩影片 ID，不建議。

## 常見退回原因

- 權限說明寫得太籠統（例如只寫「需要 storage 才能運作」）
- 單一用途描述包含多個不相關的功能
- 截圖含有其他品牌的商標或無法辨識的內容
- zip 內含測試檔、node_modules 或 `.git`
- 版本號沒有遞增就重新上傳
